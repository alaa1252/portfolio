Overview

This project applies Long Short-Term Memory (LSTM) neural networks to the problem of cryptocurrency price prediction. The model is trained on historical Bitcoin OHLCV (open, high, low, close, volume) data and produces short-horizon price forecasts. A live web dashboard displays predicted vs. actual prices, model confidence, and historical accuracy metrics.

The application is deployed live on Render. The model runs server-side, and the frontend fetches predictions via a REST API.

Problem

Cryptocurrency markets are highly volatile and non-stationary, making them a challenging but widely studied domain for time-series forecasting. The goal was to implement a proper ML pipeline — data acquisition, feature engineering, model training, evaluation, and deployment — and expose it through a usable interface rather than just a Jupyter notebook.

How the Model Works

  • Historical OHLCV data is collected and cleaned, removing gaps and outliers
  • Prices are normalised using MinMaxScaler to the [0, 1] range for stable training
  • A sliding window of N past timesteps is used as input to predict the next closing price
  • The LSTM network learns temporal dependencies across the input sequence
  • Predictions are inverse-transformed back to USD for display
  • Model performance is tracked with RMSE, MAE, and directional accuracy (did it predict up or down correctly?)

Challenges

Overfitting on Volatile Data

Cryptocurrency price data is highly non-stationary — patterns that held for months can reverse overnight. Combating overfitting required dropout layers, early stopping, and a walk-forward validation strategy that better reflects real forecasting conditions than a simple train/test split.

Deploying a Trained Model as a Live API

Packaging a Keras model and scaler together, loading them correctly at server startup, and exposing predictions through a stateless REST API required careful serialisation. Model and scaler are saved as separate files and loaded into memory once on startup rather than on every request.

Communicating Uncertainty Honestly

Price prediction models are frequently misleading when presented without caveats. The dashboard explicitly displays error metrics and uses a confidence band rather than a single predicted price, making it clear what the model can and cannot claim.

What I Learned

This project taught me that the hardest part of ML engineering is not the model — it's the pipeline around it. Data cleaning, proper validation, serialisation, and serving are where most of the engineering work lives. I also developed a much more grounded intuition for when ML models are genuinely useful and when they are noise dressed up as signal.
