Assist Vest

Raspberry Pi wearable for visually impaired users — real-time YOLOv8 object detection, GPS tracking, ultrasonic obstacle sensing, and a live WebSocket dashboard.

Live Dashboard GitHub Watch Demo ↓

Overview

Assist Vest is a wearable assistive device designed for visually impaired users. A Raspberry Pi mounted in a vest processes live camera input through a YOLOv8 object detection model, reads data from ultrasonic distance sensors and a GPS module, and streams everything in real time to a remote web dashboard via WebSocket. The system provides both on-device audio alerts and remote monitoring by a caregiver.

The live dashboard is deployed at GitHub Pages. It requires the physical vest hardware to be active and on the same network for real telemetry — a normal constraint for any hardware-dependent system.

Problem

Assistive technology for the visually impaired is either prohibitively expensive or limited to single-function devices (cane, single sonar). The goal was to design an integrated wearable that combines spatial awareness, object recognition, location tracking, and remote monitoring into a single affordable platform built on off-the-shelf components.

Deployment

Dashboard hosted on GitHub Pages · Pi runs headless Python service on boot

Key Features

  • Real-time YOLOv8 object detection — identifies people, vehicles, obstacles, and common objects
  • Ultrasonic proximity alerts for close-range obstacle avoidance with audio feedback
  • Live GPS tracking visible on an interactive map in the web dashboard
  • Temperature and environmental monitoring streamed alongside other telemetry
  • Emergency alert system — caregiver can be notified of unusual stops or falls
  • WebSocket-based live feed with sub-second latency on local network
  • Headless auto-start: Pi boots and connects without any user interaction on the device

Challenges

YOLOv8 Performance on Raspberry Pi

Running a full YOLOv8 model at acceptable frame rates on the Pi's CPU required tuning: using the nano model variant, downscaling inference resolution, and batching frames to trade latency for throughput. The result was a usable detection rate for real-world walking scenarios.

Sensor Data Fusion

Synchronising output from four different sources — camera, two ultrasonic sensors, GPS, and temperature — into a single coherent WebSocket message required careful timestamping and a central data aggregation loop on the Pi to avoid stale or mismatched readings.

WebSocket Stability Over Wi-Fi

The Pi's Wi-Fi connection could drop or degrade during movement. Added automatic reconnection logic on both the Pi and the dashboard client, with graceful degradation — the dashboard shows a "Reconnecting…" state rather than crashing when the connection drops.

Power & Heat Management

Running YOLOv8 continuously caused CPU throttling due to heat. Solved by adding a cooling heatsink, throttling inference to only run when ultrasonic sensors detect proximity below a threshold, and implementing sleep cycles when the user is stationary.

What I Learned

This project was my deepest dive into the intersection of software and physical hardware. I learned how to design systems with real-world constraints — battery life, thermal limits, wireless reliability — that don't exist in pure software projects. Working with YOLOv8 at the edge taught me a lot about model optimization trade-offs. And building something with a genuine social purpose changed how I think about what software is for.
